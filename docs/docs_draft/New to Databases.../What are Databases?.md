# What in the world is a *Database*?

Fundamentally the idea of storing data is neat organisation and space. Everything *is* data, and rarely do things/objects in some sort of systematic setting not have a relationship in some way to one another:

> Take a moment without thinking to hard about a environment or system you use or are in everyday. Could be something like your job, the grocery store, a school, etc. and thing about how within those environements/system the relationship between things? In a grocery store, food is organised by similar sections, dry foods and wet foods are grouped together respectively. In school you have students grouped by classes, organised by last names, who are then further grouped by an assigned teacher and subject. General organisation tells us that is it useful to group similar things, as well as group things by relation. 

This thought example is the exact thought process behind database theory. Sparing any actual techincal discussion, the implementation of most databases is shockingly analog to how most humans would intutively try and group things within a given systems, with some syntactic and computational flavoring. This idea is behind the creation of DBMS (Database management systems) that are used/query mostly by a query language called SQL (pronounced "SEQUEL")  meaning "Structured Query Language". SQL is the language behind manipulating data within some database. Now before we dive a bit more into DBMS & SQL, there should be some general prefaces to cover. 

- SQL is not the only style for working with DBMS, and there are multitudes of different types of database systems for different kinds of organisation problems. We are diving into SQL because it lends itself well to understanding how databases work more generally, and because it is by far the most commonly used query system that is the backbone of most ORM (Object Relational Mapping) technology and thus transitively PikaORM.
- If you are seeking an explaination for *how* databases work internally, you will be slightly disappointed by this guide as this is intended to pragmatically understand the usage of a database. If you would like to learn more wikipedia does a shockingly good job at an in depth overview and is a great [starting place.](https://en.wikipedia.org/wiki/Database)
